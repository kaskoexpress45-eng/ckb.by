# CKB.by

Next.js + TypeScript. Приоритет главной — продажи, переговоры и развитие руководителей. Шесть основных страниц; защита и капитал сохранены как дополнительные направления. Сайт пока не опубликован.

## Запуск

Требуется Node.js 24 (использован 24.19.0) и npm. Команды выполняются в `/workspace/ckb.by/site`:

```sh
export npm_config_cache=/tmp/ckb-npm-cache
npm ci
npm run dev -- --hostname 0.0.0.0
```

Проверки: `npm run lint`, `npm test`, `npm run build`. Браузер: `CKB_TEST_DISABLED_INTAKE=1 npm run test:browser` при запущенном локальном сервере и отключённом приёме заявок. Chromium берётся из `/usr/bin/chromium`, CHROMIUM_EXECUTABLE_PATH или установленного Playwright. Обычный `npm run test:browser` не отправляет валидные заявки во внешние каналы. Production: `npm start -- --hostname 0.0.0.0` после сборки. Использовать существующий checkout, не создавать Git worktree без прямого запроса пользователя.

## Контакты и переменные

Полный список имён — `.env.example`. Значения секретов хранить в защищённых настройках среды/хостинга, не в Git и не в чате. Файлы `.env*` игнорируются, кроме `.env.example`.
Публичные контакты `NEXT_PUBLIC_PHONE`, `NEXT_PUBLIC_TELEGRAM_URL`, `NEXT_PUBLIC_EMAIL`, `NEXT_PUBLIC_INSTAGRAM_URL` задаются только реальными значениями владельца. Для Telegram — полный адрес https://t.me/username. Прямые действия скрыты, пока контактов нет.

Приём заявок закрыт (`LEAD_INTAKE_ENABLED=false`). Сначала:
1. Подтвердить сведения оператора, сроки и порядок обработки данных; заменить черновик `app/politika/page.tsx` согласованной политикой. Получить согласие на публикацию кейсов и стажа.
2. В Supabase SQL Editor выполнить `../supabase/leads.sql`. Таблица закрыта RLS без публичных политик. Задать серверные SUPABASE_URL и SUPABASE_SECRET_KEY (секретный ключ, не публичный).
3. Создать Telegram-бота через BotFather, нажать Start. Сохранить TELEGRAM_BOT_TOKEN в защищённых настройках. `npm run telegram:chat-id` выводит только ID доступных чатов, не токен. Задать TELEGRAM_CHAT_ID.
4. Включить `LEAD_INTAKE_ENABLED=true`, пересобрать/перезапустить и выполнить реальный тест: строка в Supabase и уведомление Telegram. Проверка доставки с реальными доступами пока НЕ выполнена.

Достаточно одного успешно принявшего канала для ответа «заявка принята»; сбой второго отмечается в серверном логе без персональных данных. Параллельные отправки защищены локальным лимитом 5 за 10 минут на IP. В нескольких инстансах нужен общий rate-limit либо защита на reverse proxy. Заголовок x-forwarded-for должен задаваться доверенным хостингом, исключающим подмену. Перед публичным запуском включить лимиты на платформе. Повторная ручная отправка после сетевого сбоя может создать дубликат — проверять контакты при обработке.

## Аналитика

Необязательный числовой NEXT_PUBLIC_YANDEX_METRIKA_ID. Скрипт подключается после отдельного согласия; поля формы не передаются в события. События: consultation_click (с направлением), telegram_click, phone_click, lead_success. Просмотры и источники отслеживаются счётчиком, UTM заявки — в базе. Качество обращения и продажи нужно отмечать в CRM/журнале. После запуска создать цели в Метрике и проверить их реальными переходами. Без ID сторонние скрипты не загружаются. Домен mc.yandex.ru необходимо разрешить сетевой политикой при тестировании из этой среды.

## Публикация

Нужен отдельный порученный запуск и доступ к хостингу. Vercel Root Directory: site. Для коммерческого сайта тариф Hobby не подходит — выбрать Pro или другой хостинг. HTTPS, домен и реальные заявки проверяются после публикации.
Внести NEXT_PUBLIC_SITE_URL с итоговым HTTPS-адресом. SITE_INDEXABLE=false по умолчанию: превью не индексируется. Перед открытием публичного сайта переключить true, пересобрать, проверить robots/canonical/sitemap и обновить public/llms.txt, если изменился домен.
Для доставки разрешить api.telegram.org и точный домен проекта Supabase; проект Supabase пока неизвестен. Никакие secret/proxy credentials в код не встраивать.
